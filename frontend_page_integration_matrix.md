## 2. Contradictions between Documentation and Implementation

During the verification audit, the following contradictions were identified:

### 1. Company Logo Required Fields Validation
*   **Documented Behavior:** The [backend_frontend_integration_plan.md](file:///e:/AdaptCRM/JWTCRM-Backend/backend_frontend_integration_plan.md) and User Requests state that `companyLogo` must be optional during registration and succeed even if no logo is uploaded.
*   **Actual Backend Behavior:** Django backend serializers have been successfully updated to omit `companyLogo` from required fields validation, allowing registrations to pass without a file.
*   **Actual Frontend Behavior:** `RegistrationPage.jsx` has a `getMissingField` helper function that checks all fields inside the state:
    ```javascript
    const getMissingField = () =>
        Object.entries(form).find(([, value]) => {
            if (value instanceof File) return false;
            return String(value || '').trim().length === 0;
        });
    ```
    Since `companyLogo` is initialized as `null` (which is not an instance of `File` and resolves to empty string length `0`), `getMissingField` flags the logo as missing and triggers a validation alert blocking submission.
*   **Impact on Integration:** First-time registration will fail on the frontend if no logo file is selected.
*   **Recommended Resolution:** Modify `RegistrationPage.jsx`'s `getMissingField` check to explicitly ignore `companyLogo`.

### 2. Missing JTS Password Reset Confirm View
*   **Documented Behavior:** The integration plan documents a React "Password Reset Recovery Form" mapping to `/api/auth/reset-password/confirm/`.
*   **Actual Backend Behavior:** Django backend provides `POST /api/auth/reset-password/confirm/` for password recovery.
*   **Actual Frontend Behavior:** The JTS portal does not contain any reset password confirmation page in `frontend/src/jts/` or `JtsPortalSection.jsx`.
*   **Impact on Integration:** Users clicking the recovery link in emails will have nowhere to input new passwords within the React application.
*   **Recommended Resolution:** Implement `PasswordResetConfirm.jsx` from scratch, parse token and uid parameters on mount, and post the data.

### 3. CRM Roles & Permissions Matrices
*   **Documented Behavior:** PermissionsPage and RolesPage are documented as ready mapping to Django REST APIs.
*   **Actual Backend Behavior:** Django backend implements `/api/roles/` and `/api/roles/<id>/permissions/`.
*   **Actual Frontend Behavior:** The frontend saves and loads permission matrices strictly from local browser storage (`leadflow_rbac_roles`).
*   **Impact on Integration:** Permissions configured by admins are localized to single browsers and do not update active backend session permissions.
*   **Recommended Resolution:** Replace the LocalStorage code in the components with fetch requests mapping to the REST APIs.
